# Experience, evaluation, reflection, and learning

```text
Experience -> Evaluation -> Reflection -> Learning
                                      |
                         StrategyStore + KnowledgeStore
```

After a successful final provider response, Conversation stores experience in `data/experiences/experiences.jsonl`. Entry has `id`, task, response, strategy, result, and retrieved-memory count. Current live path marks completed replies `success`; provider/tool errors return before experience recording.

Strategy label is `long_term_memory` when memory retrieval returned entries, otherwise `conversation_context`.

## Evaluation

Deterministic score starts at 0.8 for success, 0.2 for failure, or 0.5 for unknown. Successful memory use adds 0.1; empty response subtracts 0.3; result clamps to 0..1. Labels: good at 0.8+, moderate at 0.5+, poor below 0.5.

## Reflection and learning

Reflector creates owned insight and recommendation text from result, score, memory usage, and strategy. Learner combines these into lesson and sets:

- `keep_strategy` at score >= 0.8
- `observe_strategy` at score >= 0.5
- `reconsider_strategy` below 0.5

Confidence is distance from neutral score 0.5, scaled to 0..1. This pipeline is deterministic; it does not retrain provider model.

## Strategy persistence

`data/learning/strategies.jsonl` aggregates uses, successes (score >= 0.7), failures, average score, confidence, last score, and last action. Selection excludes `reconsider_strategy`, ranks weighted average/confidence/last score, and breaks ties lexically. Selected strategy becomes provider-context guidance.

## Knowledge generated by learning

Lesson is upserted to `data/knowledge/knowledge.jsonl` using strategy as topic, source `learning`, and learning confidence. Same topic replaces content/source/confidence. Conversation retrieves at most 3 entries through case-insensitive query substring matching against topic/content. No embeddings or vector DB.

**Since M4**, the lesson is no longer upserted automatically: the pipeline output becomes a `lesson` **proposal** in `data/proposals/proposals.jsonl`, and the strategy/knowledge stores are updated only after a human validates and manually applies an accepted proposal (see [learning proposals](learning-proposals.md)). The pipeline text above describes how the lesson and action are derived; promotion requires validation.

Experience store rewrites JSONL directly. Strategy and knowledge use atomic replacement. Persistence failures are logged and may leave in-memory updates newer than disk.
